### Фаза 5: Оптимізація під профіль V8 (M3)
- **Крок 5.1 (Пули об'єктів)**:
  - Створено `ObjectPool<T>` (`shared/sim/pool.ts`) з методами `acquire()`, `release()`, `preallocate()`.
  - Застосовано для куль на сервері та клієнті, та часток вибухів `Particle` на клієнті. При кожному `acquire` призначається новий унікальний `id`, а при `release` обнуляються всі посилання.
- **Крок 5.2 (Zero `new Vector2` у гарячому циклі)**:
  - Розширено `Vector2` мутабельними методами `mut_set`, `mut_add`, `mut_addScaled`, `distanceTo`, `distanceSq`.
  - Усі перевірки колізій та оновлення позицій переведені на скалярні змінні `(x, y)` та `mut_set`, усунувши створення нових об'єктів векторів щокадру.
- **Крок 5.3 (Стабільні Hidden Classes)**:
  - Усі класи та об'єкти сутностей ініціалізують поля в строго однаковому порядку (`id, kind, x, y, vx, vy, angle, hp`) з однаковими типами.
  - Усунено деструктуризацію `{ ...to }` у гарячому циклі.
- **Крок 5.4 (Усунення генераторів `*ofKind` та проміжних масивів)**:
  - Додано кешований масив `#entityList` у `World` та метод `forEachOfKind(kind, fn)`.
  - В `interpolatedEntities` прибрано створення двох `Map`, `Set` та масивів `.map()`, застосовано єдину попередньо виділену структуру пошуку з проходом $O(N)$.
  - Черга `pendingInputs` фільтрується за місцем (in-place) без алокацій.
- **Крок 5.5 (Оптимізація Canvas рендерингу)**:
  - Скомпільовано кешовані контури `Path2D` (`shipPath`, `asteroidPath`).

- **Крок 5.6 (Серверний pre-encoded бінарний зріз)**:
  - Базовий бінарний снепшот серіалізується один раз за тік, після чого для кожного клієнта створюється зріз `buffer.slice(0)` із патчем `lastProcessedSeq` за зміщенням 6 (скорочення операцій кодування у 128 разів).
- **Результати після оптимізацій (`after`)**:

  - Час кадру p99: **0.20 мс** (-33.3%)

### Фаза 6: Просторовий хеш для колізій (Spatial Hash vs Naive)
- **Реалізація**: `shared/sim/spatialHash.ts` (`SpatialHashGrid`) із комірками $64 \times 64$, детерміністичним обходом та впорядкуванням пар за ID.
- **Тестування еквівалентності**: У `shared/test/spatialHash.test.ts` реалізовано property-тест (`fast-check`) на 300 випадкових конфігураціях (100% збіг знайдених колізій із наївним алгоритмом $O(N^2)$).
- **Бенчмарк (`npm run bench:collisions`)**:
  - При $N = 16$: наївний алгоритм швидший у 16.5 раза (0.0005 мс vs 0.0079 мс).
  - При $N = 32$: наївний алгоритм швидший у 9.8 раза (0.0010 мс vs 0.0099 мс).
  - При $N = 64$: наївний алгоритм швидший у 5.2 раза (0.0028 мс vs 0.0144 мс).
- **Інженерне рішення**: Для розмірів кімнати dogfight арени ($N \le 64$) наївний алгоритм із простими скалярними перевірками відстані `dx*dx + dy*dy < radSum*radSum` у V8 JIT є значно ефективнішим за оверхед розподілу по комірках та дедуплікації хеш-ключів.

### Фаза 7: Експеримент із Web Worker (A/B тестування)
