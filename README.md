# Lab 02: Objects, Prototypes, and Classes

## Проблема `this` (Баг з подіями)
Якщо передати функцію як колбек, наприклад `window.addEventListener('keydown', ship.fire)`, ключове слово `this` всередині `fire` "загубиться" і вказуватиме на `window` (або `undefined`), через що гра зламається[cite: 15, 16]. 
**Рішення:** Я використав стрілочну функцію як поле класу (`fire = (world) => {...}`). Стрілочні функції не мають власного `this` і завжди беруть його з місця, де вони були створені (лексичне середовище)[cite: 15, 16]. Інший варіант — виклик через обгортку: `() => ship.fire()`.

## Композиція замість глибокої ієрархії (Composition over Inheritance)
Замість створення глибокого дерева наслідування (`Entity -> MovingEntity -> HomingBullet`), я використав композицію. Самонаведення кулі — це просто властивість `this.homingTarget`. Якщо вона є, логіка в `update` додає вектор тяги. Так само `Pickup` (аптечка) — це базова сутність без складного дерева[cite: 16]. Це робить код гнучким: ми можемо дати самонаведення астероїду, просто додавши йому одну змінну, без зламу архітектури[cite: 16].

## Використання Map
Для зберігання сутностей використовується `Map`, оскільки він гарантує збереження типів ключів (числовий `id` залишається числом, а не стає рядком як у звичайному об'єкті `{}`), має вбудований метод `.size` та дозволяє легко ітеруватися через `for...of`[cite: 15, 16].
